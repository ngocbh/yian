VERDICT: NEEDS_REVISION

## Summary Assessment

The final target matches the accepted design, but the staged implementation plan is not executable as written. In particular, #117 cannot make the run log authoritative while transparently adapting checkpoint resume, and #118 cannot safely merge blocking terminal input before the main-thread broker and same-PR contract updates exist.

## Critical Issues (must fix)

1. **#117's Pause/checkpoint adapter has no coherent single-log lifecycle.** Slice 3.8 closes the writer in `finally` (`plan:546`), then Slice 3.9 says a legacy `engine=` or `checkpoint=` answer appends a normal `NodeSucceeded` (`plan:560-565`). Neither legacy resume signature carries the log path/writer, and today's `RunCheckpoint` stores only pool/frontier/dispositions/pause/growth/worker state (`suspension/checkpoint.py:87-107`), not run ID, log path, sequence, or record history. For an explicitly logged run that pauses, the JSONL therefore ends at `NodeStarted`; resuming by checkpoint can succeed while the original authoritative log remains unfinished, and subsequent log-only recovery retries the pausing node. A live engine also cannot append through the writer that Slice 3.8 closed unless an unplanned reopen/lock/sequence protocol is added. Decide one enforceable transition: combine #117 and #118, land blocking interaction before authoritative logging, or explicitly forbid/make unlogged every legacy pause arm. If the adapter remains, specify writer ownership and add a red test for `run_flow(log=path) -> Pause -> live/checkpoint answer -> replay the same path`; without that, append-before-reduce is not true for the compatibility path.

2. **#118 cannot safely precede #119's main-thread broker.** Once HUMAN_INPUT and agent `ask_user` block, positive-worker runs invoke terminal input in a worker while SIGINT is delivered to the main dispatcher. A lock around `questionary` does not wake that worker, coordinate Rich rendering, or let structured drain release the JSONL lock. This is the exact lifecycle the final design requires `TerminalBroker` to solve (`design-final:336-364`). The temporary handler at `plan:644` is therefore insufficient for `num_workers > 0`, Ctrl-C, and concurrent progress/prompt output. Move broker Slice 5.1 and its cancellation plumbing ahead of or into the blocking cutover; do not merge #118 with worker-thread terminal I/O.

3. **#118 also cannot pass its stated full-suite gate because authoring artifacts move only in #119.** Slice 4.4 removes the `controls:` field, but `examples/ask-user.yaml` still authors it and `tests/examples/test_examples.py:17-23` loads every example. The composing skill and active syntax docs also continue teaching `controls:` and checkpoint suspension until Slice 5.5. This violates the project rule that syntax, engine API, docs, skills, examples, and templates change in the same PR. #117 similarly changes `run_flow`, `resume_flow`, `RunResult`, observers, and durability without its API/engine docs. Move each surface's docs, seeds, templates, examples, and docstrings into the PR that changes it, or make #117-#119 a single breaking-cutover PR.

4. **Slice 2.5 would reintroduce cross-callsite LLM leakage.** It says to remove per-child deep copies because #34 deep-copies the root (`plan:394`). That premise is false: `copy.deepcopy(root)` preserves shared-reference aliasing. I verified that two calls to one memoized def share the same `child` before and after root deepcopy; with nested parent flows carrying different LLM layers and the per-child copy disabled, both paths ended with the later parent's `anthropic` config. The existing code explicitly copies each child for this reason (`compile/llm_cascade.py:6-9,47-51`). Keep per-callsite de-aliasing, or introduce and test an equivalent graph-clone routine. Add a regression with two parent paths that share a leaf child but inherit different providers.

5. **The seed-first transition commits a broken tree before its consumers are migrated.** Slice 2.1 replaces `Grow(subgraph, ..., seed=...)` with `Grow(seed, prune)` and commits immediately, while CALL, MAP, LOOP, AGENT, runtime replay, and tests still construct/read `subgraph` until Slice 2.3. Current calls such as `Grow(call_subgraph(...), seed=record)` (`nodes/call/node.py:80-85`) will raise `TypeError`, so that commit is not green despite its narrow test command. Make the carrier change, every producer, `build_grow`, runtime injection, compatibility replay, and affected direct-engine tests one atomic green slice, or add a deliberately temporary compatible carrier and remove it in the same PR. Also state how public direct `FlowEngine.restore(...)` callers obtain `grow_builder`; removing `replay_grow` while only `run.py` injects the builder is an undocumented break.

6. **The plan is not actually decomposed into 2-5 minute, independently verifiable tasks.** Examples include moving all disposition/join logic and building `RunState` in one step (`plan:472`), implementing parallel dispatch plus structured drain in two steps (`plan:530-533`), and deleting suspension, rewriting five recovery suites, changing both public APIs, and adding CLI compatibility in one slice (`plan:638-652`). Slice 4.3 adds replacement tests to files whose existing tests all assert `Pause`; after Slice 4.4 those whole-file commands cannot become green until the old tests are rewritten in Slice 4.6, so there is no code+test+green commit boundary. Split these into named tests and small reducer operations, put replacement tests in separate modules or select exact node IDs, and move the prefix matrix before the implementation it validates rather than adding it at the merge gate.

7. **Several commit commands omit the new files they claim to commit.** `git commit -am` does not stage untracked files. It is used after creating `test_grow_builder.py`, `manifest.py`, `test_flow_identity.py`, `runtime/log.py`, `test_run_records.py`, `runtime/state.py`, multiple new recovery tests, `test_tool_registry.py`, and `cli/terminal.py`. Replace these with explicit `git add <paths> && git commit ...`; otherwise the executable plan silently produces incomplete commits and later test commands import files that were never committed.

8. **Direct `FlowEngine` compatibility is asserted but not designed.** The plan says it remains public and runnable, yet the new reducer requires a `RunStarted` identity/pool/config transition and dynamic execution requires an injected compile-owned builder. There are many current direct dynamic users (`test_expand.py`, `test_map.py`, `test_loop_run.py`, `test_durable_replay.py`, and `test_engine_expansions_ledger.py`), but the file lists and test-first steps do not define the final constructor/default behavior or update those call sites. Add an explicit direct-engine API task covering static execution, dynamic execution with `grow_builder`, memory-log initialization, and restore removal; its tests must be green in #116, #117, and #118 respectively.
